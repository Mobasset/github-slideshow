CTR Events Decoded
Ericsson Cell Trace event types and payload offsets
Event IDNameKey PayloadUse
0x49 INTERNAL_EVENT_UE_MOBILITY_EVAL Bytes 48–50: RSRP, RSRQ, SINR (raw − 140) Serving-cell RSRP → rsrp_dbm
0x0b RRC_MEASUREMENT_REPORT Word at offset 42: bits 8–14 = RSRP, bits 2–7 = RSRQ Triggered/neighbour RSRP → meas_rsrp_dbm
0x10 INTERNAL_PROC_HO_EXEC_X2_OUT Offset 98, u16BE: TA raw (÷16 = TA-cmd units) TA source — propagated ±2 s same cell to all events
0x1e/1f RRC_RLF / Re-establishment Event flags RLF counter
0x34 NR_SCG_FAILURE Event flags SCG failure counter
0x03 INTERNAL_PER_RADIO_UE_MEASUREMENT SINR histogram bins, CQI Per-radio SINR / CQI
Cell ID formula:  cell_id = eNB_ID × 1000 + local_cell_id  ·  TA distance:  TA_cmd × 78.125 m/step  ·  RSRP raw:  raw_byte − 140 = dBm
RSRP
Two Separate RSRP Fields
0x49 serving-cell RSRP vs 0x0b measurement-report RSRP are fundamentally different
rsrp_dbm — Serving Cell RSRP

Source: 0x49 INTERNAL_EVENT_UE_MOBILITY_EVAL
Reflects the UE's actual serving cell signal strength at the mobility evaluation point.
Unbiased — best for raster coverage maps.

meas_rsrp_dbm — Meas. Report RSRP

Source: 0x0b RRC_MEASUREMENT_REPORT
Triggered only when RSRP crosses an A3/A5 threshold — i.e. when the signal is already degraded.
Biased weak — skews histogram toward poor values.

Typical distribution difference:
rsrp_dbm (serving)
–80 to –95 dBm
meas_rsrp_dbm
–100 to –115 dBm
enrichSamplesWithServingRsrp()

Propagates 0x49 serving RSRP onto nearby 0x0b records within ±5 s, same cell, RNTI-priority matching. Fills rsrp_dbm on measurement-report events so geolocation uses a reliable distance estimate.

Geolocation
Per-Sample Geolocation (C-SW VDT)
applyVdtLocalization() — matches the C-SW VDT raster engine exactly
  • 1️⃣ Serving cell anchor — each sample starts at its serving cell's lat/lon from the Cell DB.
  • 2️⃣ Distance from TA — Timing Advance (TA-cmd × 78.125 m) gives radial distance when available (0x10 events, ±2 s propagation).
  • 3️⃣ RSRP path-loss fallback — when no TA: d = 50 × 10^((−RSRP − 60) / 35) m. Gives ≈180 m at −80 dBm, ≈1340 m at −110 dBm.
  • 4️⃣ Direction = azimuth ± spread — RNTI hash XOR'd with 5-second time-bucket gives a stable-but-varying angle within the beam. Eliminates single-ray clustering.
✗ No RNTI grouping  ·  ✗ No cross-cell centroid  ·  ✗ No triangulation
✓ One independent placement per event — identical to C-SW VDT pipeline
Raster
Raster Grid Aggregation
Fixed geographic pixel grid — same mechanism as C-SW VDT raster output
  • 🟦 Fixed grid — pixel size configurable (default 50 m). Each pixel covers a fixed lat/lon cell regardless of sample density.
  • 📥 Snap — every geolocated sample is snapped to the pixel it falls inside using floor division on lat/lon.
  • 📐 Aggregate — all samples in a pixel are combined: Median (default), Average, Max, or Min.
  • 🎨 Color — pixel value mapped to 3GPP-standard RSRP/RSRQ/SINR color bins from the legend.

Geolocation
Sector Spread Seeding
Why RNTI alone fails — and the fix
❌ Problem: RNTI-only seed

If spread angle = hash(RNTI) only, every sample from the same UE session lands on the same ray. Creates radial streaks instead of a distributed raster — visually wrong and statistically wrong.

✅ Fix: RNTI ⊕ time-bucket

Each 5-second window produces a different angle offset for the same RNTI. Samples from the same UE fan out across the beam over time — matching how the UE physically moves within the sector coverage area.

// 5-second time bucket const tBucket = ( Math.floor(ts / 5000) * 0x85EBCA77 ) >>> 0; // RNTI identity hash const rntiHash = Math.imul( rnti, 0x9E3779B9 ) >>> 0; // Combined seed const h = (rntiHash ^ tBucket) >>> 0; // Angle within ±beamSpread const frac = ((Math.imul( h, 1664525) + 1013904223 ) >>> 0) / 4294967296; const angle = cell.az + (frac - 0.5) * spread * 2;

Summary
Key Design Decisions
What makes this tool match C-SW VDT behaviour
  • ✅ Per-sample placement, not triangulation. C-SW VDT places each sample independently at (cell + TA + azimuth). No cross-cell centroid, no RNTI windowing. This tool replicates that exactly.
  • ✅ Separated RSRP fields. rsrp_dbm (0x49) = unbiased serving-cell RSRP for coverage maps. meas_rsrp_dbm (0x0b) = triggered/neighbour RSRP for mobility analysis. Never mixed.
  • ✅ TA-first distance. When 0x10 TA is available (±2 s propagation, 99% hit rate in dense files), it overrides RSRP path-loss fallback for much more accurate radial distance.
  • ✅ Fixed geographic raster. Pixels are grid cells, not RNTI groups. Multiple samples in the same pixel → single aggregated value (median/avg/max). Matches C-SW raster pixel semantics.
  • ✅ Single HTML file. Zero dependencies to install. Open in any browser. All parsing, geolocation, and rendering runs entirely client-side in JavaScript.
